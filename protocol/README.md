# IPC-протокол

`ipc.schema.json` это единственный источник правды для общения solana-app и solana-core.

- Транспорт: WebSocket на `127.0.0.1`, случайный порт, адрес `ws://127.0.0.1:<port>/?token=<token>`. Без верного токена сервер отвечает HTTP 401.
- Формат: JSON-RPC 2.0. Запросы идут от app к core (`RequestMap`), события идут от core к app как уведомления без `id` (`EventMap`). Пакетные запросы не поддерживаются.
- Имена полей в `snake_case`.
- Сразу после подключения core присылает событие `state` с текущим состоянием.

## Сгенерированный код

| Файл | Чем генерируется |
| --- | --- |
| `protocol/ts/ipc.ts` | `pnpm -C app gen:protocol` (json-schema-to-typescript) |
| `core/solana_core/protocol/generated.py` | `cd core && uv run python scripts/gen_protocol.py` (datamodel-code-generator) |

Руками эти файлы не правим. После изменения схемы запускаем оба генератора и коммитим результат. CI падает, если сгенерированные файлы устарели.

## Коды ошибок

Стандартные коды JSON-RPC: `-32700` parse error, `-32600` invalid request, `-32601` method not found, `-32602` invalid params, `-32603` internal error.

Свои коды Solana:

| Код | Значение |
| --- | --- |
| `-32001` | Метод ещё не реализован (его пакет не смержен) |
| `-32002` | Не найдено (инструмент, сервер, скилл, модель) |
| `-32003` | Конфликт (например, MCP-сервер с таким именем уже есть) |

## Как менять протокол

Протокол общий для всех пакетов, поэтому изменения идут отдельным маленьким PR, который согласует владелец проекта. Добавлять необязательные поля можно без смены `protocol_version`; удаление и переименование полей или методов требует поднять `protocol_version`.
