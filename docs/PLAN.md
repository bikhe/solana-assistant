# Solana: план разработки для агентов

Версия от 30.10.2026. Исходник плана: [Claude Doc](https://claude.ai/artifact/QpvYjt3SufqcFfHaaDRzn2).

## Как пользоваться планом

Работа разбита на 15 пакетов (WP) в четырёх фазах. Фазу 0 делает один агент, после неё параллельно работают до семи агентов, затем до четырёх.

Правила для каждого агента:

1. Один пакет = один агент = одна ветка `wp-<номер>-<slug>` = один PR в `main`.
2. Агент меняет только папки своего пакета. Контракты из `protocol/` и базовые классы меняются отдельным маленьким PR, который согласует владелец проекта.
3. Всё внешнее (микрофон, сеть, модели, ОС) спрятано за интерфейсом, у которого есть Fake-реализация для тестов. Поэтому пакеты не ждут друг друга.
4. PR принимается, когда CI зелёный на Windows, Linux и macOS, а критерии приёмки пакета выполнены.
5. Цифры в критериях приёмки (задержки, проценты) это целевые значения, а не измеренные. Агент меряет их и пишет результат в PR.

Порядок волн:

```
Волна 1 (1 агент)   Волна 2 (до 7)              Волна 3 (до 4)            Волна 4 (до 5)
WP0 Каркас и IPC -> WP1 Wake word, VAD       -> WP6 Конвейер голоса    -> WP10 Память
                    WP2 STT и TTS               (после WP1–WP3)           (после WP3)
                    WP3 LLM и диалог            WP7 MCP (после WP3)       WP11 Интеграции
                    WP4 Оболочка Tauri          WP8 Скиллы (после WP3)    (после WP7, WP8)
                    WP5a/b/c Управление ПК      WP9 Безопасность          WP12 Английский
                    WP13 Сборка, релизы         (после WP3)               (после WP6)
                                                                          WP14 Дизайн и образ
                                                                          (после WP4)
```

Каждая волна стартует, когда смержены пакеты, указанные в «после…». WP13 и WP14 можно взять раньше, если есть свободный агент.

## Архитектура и контракты

Два процесса. **solana-core** на Python 3.12 (asyncio) делает всю работу: аудио, wake word, распознавание, синтез, LLM, инструменты, MCP, скиллы и настройки. **solana-app** на Tauri 2 + TypeScript + React показывает трей, оверлей, чат, настройки и мастер первого запуска. Приложение запускает core как sidecar и общается с ним по WebSocket на 127.0.0.1 со случайным портом и токеном.

Структура репозитория:

```
solana-assistant/
  core/                  Python, uv
    solana_core/
      server/            WebSocket + JSON-RPC
      config/            настройки, секреты
      audio/  wake/      микрофон, VAD, wake word
      stt/  tts/         распознавание и синтез речи
      brain/             LLM-провайдеры, диалог
      tools/             реестр инструментов, политика разрешений
      pc/                управление ПК (windows/ linux/ macos/)
      mcp/  skills/      MCP-клиент, загрузчик скиллов
      memory/            память о пользователе
      pipeline/          голосовой конвейер
    tests/
  app/                   Tauri 2 + TS
    src/  src-tauri/
  protocol/              JSON Schema + сгенерированные TS-типы
  skills/                встроенные скиллы
  models/                скрипты обучения wake word (веса не в git)
  docs/
  .github/workflows/
```

Общие контракты (их создаёт WP0, остальные только реализуют):

| Контракт | Где | Суть |
| --- | --- | --- |
| IPC-протокол | `protocol/ipc.schema.json` | JSON-RPC 2.0 поверх WebSocket. Запросы app → core: `settings.get/set`, `chat.send`, `voice.mute`, `confirm.reply`, `mcp.*`, `skills.*`, `models.download`. События core → app: `state`, `transcript.partial/final`, `assistant.delta/done`, `tool.started/finished`, `confirm.request`, `download.progress`, `error` |
| Состояние ассистента | там же | `idle` → `wake` → `listening` → `thinking` → `speaking` → `idle`, плюс `muted` и `error` |
| Провайдеры | `core/solana_core/*/base.py` | `AudioSource`, `WakeWordDetector`, `STTProvider`, `TTSProvider`, `LLMProvider`, `PcBackend`: абстрактные классы, у каждого есть Fake |
| Инструмент | `core/solana_core/tools/base.py` | `Tool`: name, description, JSON Schema параметров, risk (`safe` / `confirm` / `dangerous`), `async run()`. В этот же формат приводятся инструменты MCP и скиллов |
| Конфиг | `core/solana_core/config/` | pydantic-модель, TOML в папке пользователя (platformdirs), ключи API в системном хранилище (keyring) |

Библиотеки по умолчанию (режим выбирается в мастере и в настройках):

| Слой | Локально | Облако |
| --- | --- | --- |
| Wake word | openWakeWord, своя модель «Эй, Солана» | нет, всегда локально |
| VAD | Silero VAD | нет |
| STT | faster-whisper, GigaAM (для русского) | OpenAI-совместимый API, Yandex SpeechKit |
| TTS | Silero TTS (ru), Piper (en) | Yandex SpeechKit, ElevenLabs, OpenAI |
| LLM | Ollama, LM Studio | Claude, OpenAI, OpenRouter, любой OpenAI-совместимый |
| MCP | официальный Python SDK `mcp` | удалённые MCP-серверы по HTTP |

## Фаза 0: каркас и контракты

Один агент, блокирует все остальные пакеты. Его задача: чтобы после него семь агентов могли работать, не мешая друг другу.

### WP0. Монорепозиторий и контракты

**Папки:** всё, кроме реализаций внутри модулей.

- [ ] Структура репозитория из раздела «Архитектура», пустые пакеты с `__init__.py`.
- [ ] Python-проект на uv: ruff, mypy (strict), pytest, pytest-asyncio. Команда `solana-core --port --token`.
- [ ] WebSocket-сервер с JSON-RPC 2.0: проверка токена, `ping`, рассылка события `state`.
- [ ] `protocol/ipc.schema.json` со всеми запросами и событиями из таблицы контрактов. Генерация TS-типов (json-schema-to-typescript) и pydantic-моделей, проверка в CI, что они актуальны.
- [ ] Абстрактные классы всех провайдеров, `Tool`, `ToolRegistry`, `PcBackend` и Fake-реализация каждого.
- [ ] Конфиг: pydantic-модель, чтение и запись TOML, ключи через keyring.
- [ ] Tauri 2 + React + Vite + Tailwind CSS: в dev-режиме запускает core через `uv run`, подключается по WebSocket, показывает статус и состояние. ESLint, Prettier, Vitest.
- [ ] Режим `solana-core --fake`: играет сценарий событий (пробуждение, транскрипт, ответ, запрос подтверждения), чтобы WP4 делал UI без настоящего голоса.
- [ ] CI в GitHub Actions на Windows, Linux и macOS: линтеры и тесты обеих частей.
- [ ] `CLAUDE.md` и `CONTRIBUTING.md` с правилами для агентов.

**Готово, когда:** `pnpm tauri dev` открывает окно со статусом «core: подключён» и меняющимся состоянием в fake-режиме; CI зелёный на трёх ОС; тест проверяет, что событие из core доходит до app.

## Фаза 1: параллельные пакеты

До семи агентов одновременно. Все пакеты зависят только от WP0 и друг друга не ждут.

### WP1. Голосовой вход: микрофон, VAD, wake word

**Папки:** `core/solana_core/audio/`, `core/solana_core/wake/`, `models/`.

- [ ] Захват звука через sounddevice: 16 кГц моно, выбор устройства, кольцевой буфер на 2 с (чтобы не терять начало фразы).
- [ ] Silero VAD: тяжёлые модели не работают, пока никто не говорит.
- [ ] openWakeWord: рантайм, настройка чувствительности.
- [ ] Скрипт обучения модели «Эй, Солана» в `models/`: синтетические примеры через русские голоса Piper и Silero, аугментация шумом и эхом, негативные примеры («салат», «саланга», «на слона»). Инструкция, как добавить свои записи.
- [ ] Скрипт оценки: доля срабатываний на записях фразы и число ложных срабатываний в час на фоновой речи (подкасты, ТВ).

**Готово, когда:** цель ≥ 90% срабатываний на 50 живых записях, ≤ 1 ложного в час на фоновой речи, < 5% одного ядра в тишине. Тесты на WAV-фикстурах без микрофона.

### WP2. Распознавание и синтез речи

**Папки:** `core/solana_core/stt/`, `core/solana_core/tts/`.

- [ ] `STTProvider`: faster-whisper, whisper.cpp (Vulkan), GigaAM, один облачный (OpenAI-совместимый `/audio/transcriptions`). Частичные результаты там, где можно. Определение языка ru/en.
- [ ] `TTSProvider`: Silero (ru), Piper (en), один облачный. Потоковая озвучка по предложениям, чтобы начать говорить до конца ответа LLM.
- [ ] Проигрывание с мгновенной остановкой (для перебивания).
- [ ] Менеджер моделей: скачивание с прогрессом (событие `download.progress`), проверка хешей, выбор размера под железо (CPU / Vulkan для AMD / CUDA); эталонная машина: RX 6600, 8 ГБ.

**Готово, когда:** цель: русская фраза в 5 с распознаётся < 1,5 с на CPU, первый звук TTS < 0,5 с. Тесты на WAV-фикстурах, таблица замеров в PR.

### WP3. Мозг: LLM и диалог

**Папки:** `core/solana_core/brain/`, `core/solana_core/tools/registry.py`.

- [ ] `LLMProvider`: Anthropic (Claude) и OpenAI-совместимый (покрывает OpenAI, OpenRouter, Ollama, LM Studio). Стриминг и вызов инструментов.
- [ ] Роутер режимов: облако / локально / гибрид. Гибрид: простые команды локально, сложные в облако, без сети всё локально. Смена провайдера без перезапуска.
- [ ] Быстрый разбор частых команд без LLM («громче», «пауза», «открой …»), чтобы они срабатывали мгновенно.
- [ ] Диалог: системный промпт персоны «Солана» (короткие устные ответы), окно истории, цикл вызова инструментов с лимитом шагов.
- [ ] `ToolRegistry`: регистрация, включение и выключение, передача схем в LLM.

**Готово, когда:** с Fake-инструментами проходят сценарные тесты на записанных ответах моделей; вручную проверено с Claude и с локальной моделью в Ollama.

### WP4. Оболочка приложения

**Папки:** `app/`.

- [ ] Трей: выключить микрофон, чат, настройки, выход.
- [ ] Оверлей вверху экрана: поверх всех окон, прозрачный, пропускает клики в покое. Анимация по состояниям, живой транскрипт, ответ, карточка подтверждения.
- [ ] Окно чата: текстовый ввод как альтернатива голосу, история.
- [ ] Настройки: вкладки Общие, Голос, Модели, Ключи, Инструменты, MCP, Скиллы (последние две пока заглушки).
- [ ] Мастер первого запуска: язык, тест микрофона, режим (облако / локально / гибрид), ключи или скачивание моделей, проверка wake word.
- [ ] Глобальная горячая клавиша «удерживай и говори», автозапуск, i18n с первого дня (ru и en).

**Готово, когда:** все экраны работают против `solana-core --fake` на трёх ОС, скриншоты в PR, есть Vitest-тесты на обработку событий.

### WP5a / WP5b / WP5c. Управление ПК: Windows, Linux, macOS

**Папки:** `core/solana_core/pc/windows/`, `pc/linux/`, `pc/macos/` (по агенту на ОС). Общие инструменты поверх `PcBackend` делает WP5a в `pc/tools.py`.

| Группа | Инструменты | Риск |
| --- | --- | --- |
| Приложения | список установленных, открыть, закрыть | safe / confirm |
| Окна | список, фокус, свернуть, развернуть, закрыть | safe / confirm |
| Звук и медиа | громкость, mute, play/pause, следующий, что играет | safe |
| Файлы | поиск, открыть, показать в папке, переместить, в корзину (без безвозвратного удаления) | safe / confirm |
| Браузер | открыть URL, поиск | safe |
| Система | буфер обмена, скриншот, батарея, уведомление, блокировка, сон, выключение | safe / dangerous |

Подсказки по библиотекам: Windows: pywinauto, pycaw, медиа через SMTC (winsdk). Linux: D-Bus (MPRIS, уведомления), pactl/wpctl, wmctrl для X11, с честными ограничениями на Wayland. macOS: AppleScript через osascript, NSWorkspace (pyobjc).

**Готово, когда:** безопасные операции покрыты интеграционными тестами на CI своей ОС; чек-лист ручной проверки в PR; недоступная на ОС функция честно возвращает «не поддерживается».

## Фаза 2: интеграция, MCP, скиллы, безопасность

До четырёх агентов. После этой фазы ассистентом можно пользоваться каждый день.

### WP6. Голосовой конвейер

**Зависит от:** WP1, WP2, WP3. **Папки:** `core/solana_core/pipeline/`.

- [ ] Машина состояний из контракта, события в app.
- [ ] Конец фразы по тишине (настраиваемо, по умолчанию около 1 с), максимум 15 с на команду.
- [ ] Перебивание: wake word или «стоп» во время ответа останавливает речь. Слова отмены: «отмена», «не надо».
- [ ] Окно продолжения: после ответа с вопросом ассистент слушает ещё несколько секунд без wake word.
- [ ] Автопауза: микрофон выключен, экран заблокирован, идёт звонок (если можно определить).

**Готово, когда:** цель: от конца фразы до первого звука ответа < 2,5 с в облачном режиме и < 1 с для быстрых команд; пройден ручной сценарий из 20 команд; есть сквозной тест на WAV-фикстурах с Fake-LLM.

### WP7. MCP

**Зависит от:** WP3. **Папки:** `core/solana_core/mcp/`, вкладка MCP в `app/`.

- [ ] Клиент на официальном SDK: транспорты stdio и Streamable HTTP, переподключение при падении сервера.
- [ ] Конфиг в формате `mcpServers`, как в Claude Desktop, с импортом из конфига Claude Desktop.
- [ ] Инструменты серверов попадают в `ToolRegistry` с префиксом сервера и риском `confirm` по умолчанию.
- [ ] UI: добавить, удалить, включить сервер; статус; список инструментов с переключателями.
- [ ] По желанию: режим MCP-сервера, чтобы Claude Desktop и Claude Code могли управлять ПК через инструменты Solana.

**Готово, когда:** подключённый filesystem MCP-сервер работает голосом; тесты на тестовом MCP-сервере в репозитории.

### WP8. Скиллы

**Зависит от:** WP3. **Папки:** `core/solana_core/skills/`, `skills/`, вкладка Скиллы в `app/`.

- [ ] Формат: папка с `SKILL.md` (frontmatter: name, description, языки), необязательные `scripts/` и `tools.py` с дополнительными инструментами. Совместим по форме со скиллами Claude.
- [ ] Постепенная загрузка: в системный промпт попадают только описания, полный текст подгружается инструментом `skill.load`.
- [ ] Установка из папки, zip или git-ссылки; скрипты скилла запускаются с подтверждением.
- [ ] Встроенные скиллы: таймеры и напоминания, погода, заметки, переводчик, «что у меня на экране» (скриншот + модель со зрением).

**Готово, когда:** пять встроенных скиллов работают голосом; скилл из примера в `docs/` устанавливается из UI.

### WP9. Безопасность и разрешения

**Зависит от:** WP3. **Папки:** `core/solana_core/tools/policy.py`, карточка подтверждения в `app/`.

- [ ] `safe` выполняется сразу; `confirm` ждёт «да» голосом или клик; `dangerous` только клик по карточке.
- [ ] «Всегда разрешать» для отдельных инструментов, кроме `dangerous`.
- [ ] Локальный журнал вызовов инструментов с просмотром в UI.
- [ ] Результаты инструментов, MCP и веб-страниц помечаются как данные, а не инструкции (защита от prompt injection).

**Готово, когда:** тесты показывают, что `dangerous` нельзя выполнить голосом или из текста инструмента, а журнал пишется для каждого вызова.

## Фаза 3: память, интеграции, английский, сборка, дизайн

До пяти агентов. WP13 и WP14 можно начать раньше, уже во второй волне, если есть свободный агент.

### WP10. Память о пользователе

**Зависит от:** WP3. **Папки:** `core/solana_core/memory/`.

- [ ] SQLite: факты о пользователе, история разговоров, векторный поиск (sqlite-vec) на локальных эмбеддингах.
- [ ] Инструменты «запомни», «что ты обо мне знаешь», «забудь»; просмотр и удаление в UI.
- [ ] Релевантные факты подмешиваются в промпт, всё хранится только локально.

### WP11. Интеграции в духе Станции

**Зависит от:** WP7, WP8. **Папки:** `skills/`, `docs/integrations/`.

- [ ] Музыка: Spotify (официальный Web API), Яндекс Музыка (неофициальная библиотека, пометить риск).
- [ ] Умный дом через Home Assistant (его MCP-сервер или REST API).
- [ ] Календарь и почта через готовые MCP-серверы; письма только черновиком, отправка кликом.
- [ ] Расследовать управление Яндекс Станцией и устройствами Алисы (через Home Assistant или неофициальный API) и написать короткий вывод до того, как делать.

### WP12. Английский язык

**Зависит от:** WP6. **Папки:** `models/`, промпты в `brain/`, переводы в `app/`.

- [ ] Вторая модель wake word «Hey Solana», обе работают одновременно.
- [ ] Язык ответа = язык вопроса; быстрые команды и промпты на английском; полный перевод UI.

### WP13. Сборка и релизы

**Зависит от:** WP0 (полностью заканчивается после WP6). **Папки:** `.github/workflows/`, `app/src-tauri/` (конфиг сборки), `core/packaging/`.

- [ ] core собирается в один бинарник (PyInstaller или Nuitka) и кладётся в Tauri как sidecar.
- [ ] Установщики: msi/exe, AppImage/deb/rpm, dmg. Модели не в установщике, а скачиваются мастером.
- [ ] Релиз по тегу в GitHub Releases, автообновление через Tauri updater. Заметки про подпись и предупреждения SmartScreen / Gatekeeper.

### WP14. Дизайн и образ

**Зависит от:** WP4. **Папки:** `app/src/` (стили, анимации), `app/assets/`.

- [ ] Свой образ Соланы (орб или персонаж) с анимацией на каждое состояние. Не копировать Mochi, имя и звуки coucou: они под авторским правом.
- [ ] Звуки: пробуждение, готово, ошибка, не поняла.
- [ ] Иконка приложения и трея, светлая и тёмная темы.

## Запуск агентов

Самый быстрый путь: четыре волны. Следующая волна стартует, когда смержены пакеты, от которых она зависит.

| Волна | Агентов | Пакеты |
| --- | --- | --- |
| 1 | 1 | WP0 |
| 2 | до 7 | WP1, WP2, WP3, WP4, WP5a, WP5b, WP5c (+ WP13, WP14, если есть свободные) |
| 3 | до 4 | WP6, WP7, WP8, WP9 |
| 4 | до 5 | WP10, WP11, WP12, остатки WP13 и WP14 |

Шаблон промпта для агента (подставь номер и название пакета):


## Открытые вопросы

- [x] UI-фреймворк: решено: React + Tailwind CSS + Framer Motion. Агенты знают этот стек лучше всего, на нём быстрее всего собрать UI, а Framer Motion даёт плавные анимации оверлея.

STT: whisper.cpp с Vulkan или GigaAM на CPU. ROCm для RX 6600 официально не поддержан, на него не рассчитываем.
