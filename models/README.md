# Модели

Обучение и оценка wake word «Эй, Солана» (WP1). Веса моделей в git не кладём: общие модели скачиваются при первом запуске, модель фразы собирается скриптами отсюда.

## Как устроено распознавание

```
микрофон (16 кГц) → Silero VAD → [речь?] → мел-спектрограмма → эмбеддинги → классификатор «эй_солана»
```

- Пока никто не говорит, работает только VAD, а тихие окна не доходят даже до него. Это меньше 1% одного ядра.
- Когда VAD слышит речь, детектор получает последние 2,5 с из кольцевого буфера, поэтому начало фразы не теряется.
- Мел-спектрограмма и эмбеддинги это общие модели openWakeWord (Apache-2.0), их рантайм в `core/solana_core/wake/openwakeword.py` даёт те же оценки, что и пакет `openwakeword`.
- Классификатор фразы маленький (две скрытых сети по 64 нейрона), он учится здесь за минуту на CPU.

Модели лежат в папке данных пользователя (`SOLANA_MODELS_DIR` переопределяет путь):

| ОС | Папка |
| --- | --- |
| Windows | `%LOCALAPPDATA%\solana\models` |
| Linux | `~/.local/share/solana/models` |
| macOS | `~/Library/Application Support/solana/models` |

Модели фраз кладутся в подпапку `wake/`, по файлу `<ключ>.onnx` на фразу. Все файлы оттуда работают одновременно (так позже добавится «Hey Solana»).

## Подготовка

```sh
cd models
uv sync
```

Нужны голоса [Piper](https://github.com/rhasspy/piper/blob/master/VOICES.md) для русского: файлы `.onnx` вместе с `.onnx.json`. Чем больше разных голосов, тем лучше модель понимает живых людей. Положи их в `work/voices/`.

Для форматов кроме WAV нужен `ffmpeg`.

## 1. Свои записи (рекомендуется)

Синтетические голоса дают основу, живые записи делают модель точной. Запиши себя и домашних:

```sh
uv run python -m wakeword record --list                       # микрофоны
uv run python -m wakeword record work/rec/positive --count 50
uv run python -m wakeword record work/rec/negative --kind negative --count 30
```

Отложи 50 записей фразы для оценки (`work/rec/test`) и не используй их в обучении.

## 2. Данные

```sh
uv run python -m wakeword generate \
  --voice work/voices \
  --noise work/noise \
  --background work/background \
  --extra-positive work/rec/positive \
  --extra-negative work/rec/negative \
  --out work/features.npz
```

- `--noise`: шум, музыка, гул улицы, чтобы подмешивать под фразу.
- `--background`: длинные записи речи без фразы (подкасты, ТВ, аудиокниги). Из них режутся отрицательные примеры, это главное средство против ложных срабатываний.
- Похожие слова («салат», «саланга», «на слона» и другие) уже в `wakeword/phrases.py`, их можно дополнять.
- `--save-examples work/examples` сохранит несколько клипов, чтобы послушать, что получилось.

Аугментация: скорость и высота голоса ±12%, реверберация (синтетические комнаты), громкость, шум с SNR 0–25 дБ.

## 3. Обучение

```sh
uv run python -m wakeword train work/features.npz --install
```

`--install` кладёт `ey_solana.onnx` в папку моделей Solana. `--negative-weight` больше (по умолчанию 5) даёт меньше ложных срабатываний ценой чуть меньшей чувствительности.

## 4. Оценка

```sh
uv run python -m wakeword evaluate work/ey_solana.onnx \
  --positives work/rec/test \
  --background work/background-test
```

Скрипт гонит записи через тот же потоковый детектор с VAD, что и ассистент, и печатает три числа против целей WP1:

| Метрика | Цель |
| --- | --- |
| Доля срабатываний на живых записях | ≥ 90% |
| Ложных срабатываний в час фоновой речи | ≤ 1 |
| CPU в тишине | < 5% одного ядра |

Для фона возьми часы записей, которых не было в обучении. `--sensitivity` подбирает порог так же, как ползунок в настройках.

## Лицензии

- Общие модели openWakeWord (мел-спектрограмма, эмбеддинги): Apache-2.0. Готовые модели фраз openWakeWord (`hey_jarvis` и др.) под CC BY-NC-SA, мы их не используем.
- Silero VAD: MIT.
- `piper-tts` (GPL-3.0) нужен только для генерации данных и в приложение не попадает. Лицензия голоса Piper указана в его карточке: проверяй её, если будешь распространять обученную модель.
